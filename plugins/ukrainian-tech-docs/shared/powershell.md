# PowerShell — виділення залежностей скрипта

Спільні правила для скіла `mindmap` і режиму `write` «оновити документи після
зміни скриптів»: як зняти виклики скрипта, віднести їх до систем, позначити дію і ступінь певності. Скриптів не виконують ні на якому кроці.

## 1. Перелік викликів парсером

Розбір — `[System.Management.Automation.Language.Parser]::ParseFile(<шлях>, [ref]$tokens, [ref]$errors)`:
він читає файл і будує дерево, нічого не виконуючи. Помилки розбору (`$errors`)
називають у звіті: файл із помилками дає неповне дерево.

З дерева знімають (метод `FindAll` з умовою на тип вузла):

| Що | Вузол | Що взяти |
|---|---|---|
| Виклики команд | `CommandAst` | `GetCommandName()`, номер рядка (`Extent.StartLineNumber`), параметри |
| Власні функції | `FunctionDefinitionAst` | ім'я і тіло — для розкриття обгорток (розд. 2) |
| Параметри викликів | `CommandParameterAst` | віддалені цілі (розд. 6), `-Path` для реєстру й файлів, `-WhatIf` |
| Підключення файлів | `CommandAst` з `InvocationOperator` = `Dot` | вираз шляху (розд. 2) |
| Динамічні виклики | `CommandAst` без імені команди; `&` зі змінною; `Invoke-Expression` | у «Невідоме» (розд. 7) |
| Звертання до .NET | `InvokeMemberExpressionAst`, `TypeExpressionAst` | клас і метод: `[System.Net.Dns]::GetHostByName` |
| Блоки в змінних | `ScriptBlockExpressionAst`, присвоєний змінній | де цей блок виконують (розд. 6) |

Запит до дерева модель пише сама під задачу; кілька коротких запитів кращі за
один великий. Повноту перевіряють числами: скільки викликів і функцій
знайдено. Різке розходження з тим, що видно в коді на око (наприклад, нуль
викликів у файлі на тисячу рядків), означає помилку в запиті, а не порожній
скрипт.

Без PowerShell перелік складають читанням коду, і звіт каже: «перелік може бути
неповним».

## 2. Власні функції, обгортки, підключені файли

- **Власна функція** — ім'я виклику збігається з означеною функцією скрипта чи
  підключеного файла. Її не відносять до системи напряму, а розкривають: які
  зовнішні команди вона викликає, зокрема через інші власні функції (замикання
  викликів). Залежність стоїть на тому рядку скрипта, де викликано обгортку.
  Ланцюжок розкривають до кінця: кожна власна функція на шляху — у скрипті, підключених файлах і файлах, які ті підключають, — має дійти до зовнішніх команд. Перед картою перевіряють: чи лишилась на шляху хоч одна власна
  функція, яку не розкрито.
- **Підключений файл** (`. <шлях>`) розбирають так само і його функції додають
  до власних. Шлях часто обчислюється (`Join-Path $PSScriptRoot '..\common\…'`):
  модель збирає його з коду; не вдалося — шлях у «Невідоме», а залежності,
  що мали б прийти із цього файла, лишаються непоказаними, і звіт це каже.
- **Функція без зовнішніх звертань** (журнал, форматування, перевірка
  аргументів) на карту не йде. Фільтр — «звертається до зовнішньої системи»,
  а не перелік заборонених імен.

## 3. Командлет → модуль

1. `Get-Command -Name <ім'я> -ErrorAction SilentlyContinue` — модуль
   (`ModuleName`) і тип (`Cmdlet`, `Function`, `Application`). Команда лише
   шукає в установлених модулях і нічого не виконує.
2. Модуля на машині немає (типово для AD, DNS-сервера, групових політик,
   Az.* на робочій станції) — модуль за іменником команди й таблицею розд. 4;
   елемент — «припущення».
3. Модуль відомий (дав `Get-Command` чи іменник), але його немає в таблиці
   розд. 4 — систему називають за призначенням модуля, з позначкою
   «припущення». У «Невідоме» такий модуль не йде.
4. Ні `Get-Command`, ні іменник не дали модуля — команда в «Невідоме».

Тип `Application` — зовнішня програма (`w32tm.exe`, `netsh.exe`): система —
сама програма й те, чим вона керує, якщо це видно з аргументів.

## 4. Модуль → система

Таблиця — відправна точка, а не повний перелік. Модуль поза нею — за
призначенням модуля з позначкою «припущення» (розд. 3, п. 3).

| Модуль чи ознака | Система на карті |
|---|---|
| `ActiveDirectory`, `ADDSDeployment` | Домен AD |
| `GroupPolicy` | Групові політики домену |
| `DnsServer` | DNS-сервер |
| `DnsClient` (`Resolve-DnsName`, `Set-DnsClientServerAddress`) | DNS вузла: розв'язання і налаштування клієнта |
| `Hyper-V` | Гіпервізор |
| `FailoverClusters` | Кластер |
| `Storage` | Сховище вузла: диски, томи, пули |
| `NetAdapter`, `NetTCPIP`, `NetLbfo` | Мережа вузла |
| `NetNat` | Мережа вузла: NAT |
| `HgsClient` (`*-HgsGuardian`, `New-HgsKeyProtector`) | Host Guardian: захист ключа ВМ |
| `Hyper-V` з `Set-VMKeyProtector`, `Enable-VMTPM` | Гіпервізор: захист ВМ (vTPM) |
| `NetSecurity` | Брандмауер вузла |
| `ServerManager` (`Install-WindowsFeature`) | Ролі й компоненти ОС вузла |
| `ScheduledTasks` | Планувальник задач вузла |
| `Microsoft.PowerShell.Management` з `-Path HKLM:\…`, `HKCU:\…` | Реєстр вузла |
| `Microsoft.PowerShell.Management` з файловим `-Path` | Файлова система — лише коли шлях поза текою скрипта |
| `Az.Accounts` | Вхід в Azure |
| `Az.KeyVault` | Azure Key Vault |
| інші `Az.*` | Azure: служба за іменем модуля |
| `Microsoft.Graph.*` | Entra ID |
| `Import-Clixml`, `Export-Clixml` з обліковими даними | Файл секретів (розд. 8) |
| .NET: `System.Net.Dns` | DNS-розв'язання |
| .NET: власний клас через `Add-Type` | Те, що клас робить за кодом; не видно — «Невідоме» |

Командлети без зовнішньої системи (`Write-Host`, `Join-Path`, `Get-Date`,
`ConvertTo-Json`, `Start-Sleep`) на карту не йдуть. `Read-Host` і
`Get-Credential` — не система, а введення людини: на карту не йдуть, а під
картою стоїть рядок «потребує введення: <що саме, рядок>».

## 5. Читає чи змінює

| Дієслово команди | Дія |
|---|---|
| `Get`, `Test`, `Resolve`, `Find`, `Search`, `Measure`, `Select`, `Compare` | Читає |
| `Set`, `New`, `Add`, `Remove`, `Install`, `Uninstall`, `Enable`, `Disable`, `Start`, `Stop`, `Restart`, `Register`, `Unregister`, `Move`, `Rename`, `Grant`, `Revoke`, `Clear`, `Reset` | Змінює |
| `Invoke`, `Update`, `Sync`, `Import`, `Export`, `Connect`, інші | Неясно — дивляться в код: що саме передано й куди |

- Виклик із `-WhatIf` нічого не змінює; так і позначають.
- Зовнішня програма — за аргументами (`w32tm /config` змінює, `w32tm /query`
  читає); не видно — «Неясно».
- Метод .NET — за назвою і кодом; не видно — «Неясно».

## 6. Віддалені цілі

Виклик працює не на машині запуску, коли має один із параметрів:
`-ComputerName`, `-CimSession`, `-Session`, `-PSSession`, `-Server`
(AD, DNS), `-Cluster`. Хост на карті — значення параметра; коли це змінна чи
вираз, показують вираз (`$Dc.HostName`), а звідки він береться — у звіті.

- `Invoke-Command -ComputerName X -ScriptBlock { … }` — команди всередині
  блоку працюють на X.
- **Блок у змінній** (`$Apply = { … }`) парсер знаходить, але не прив'язує до
  хоста. Модель шукає, де блок виконують: `& $Apply` — локально;
  `Invoke-Command -ScriptBlock $Apply -ComputerName X` — на X; обидва — обидва елементи.
- `New-PSSession`, `Enter-PSSession` — сеанс на хості; виклики з `-Session`
  ідуть туди.

## 7. Невідоме

До гілки «Невідоме» йде, а не вгадується:

- команда, модуля якої не дали ні `Get-Command`, ні іменник;
- динамічний виклик: `& $cmd`, `Invoke-Expression`, ім'я команди з рядка;
- розгортання параметрів (`@params`), коли саме воно визначає дію чи ціль;
- шлях підключеного файла, якого не вдалося обчислити;
- клас .NET, призначення якого не видно з коду;
- `Add-Type` з викликом Windows API (`DllImport`): елемент «виклик Windows API».
  Назва функції API (`LsaStorePrivateData`) може підказати систему, але лише з
  позначкою «припущення».

Біля кожного елемента — номер рядка й чому невідоме.

**Умовна залежність — не невідоме.** Виклик, що виконується лише за умови
(параметр `-Start`, змінна середовища, режим скрипта), стоїть під своєю
системою з умовою: «лише якщо `<умова>`». У «Невідоме» він іде, лише коли
невідома сама система.

## 8. Секрети

Значень паролів, ключів, токенів і рядків підключення на карті й у звіті немає.
Ознаки: змінні з `Password`, `Secret`, `Key`, `Token`, `Credential` у назві;
`ConvertTo-SecureString -AsPlainText` з рядком; `Import-Clixml` облікових
даних; рядки підключення. Показують назву: «секрет: `$AdminPassword`», «файл
облікових даних: `<шлях без імені користувача>`».

## 9. Позначки певності

| Позначка | Коли |
|---|---|
| з коду | виклик стоїть у названому рядку, модуль дав `Get-Command`, хост — у параметрі виклику |
| припущення | модуль — за таблицею без `Get-Command`; хост — зі змінної, значення якої обчислюється; шлях підключення зібрано з виразу; призначення скрипта — не з коментаря |
| невідоме | розд. 7 |

## 10. Набір скриптів

- **Напрями** — теки першого рівня набору.
- **Копії.** Файли з однаковими назвами в різних теках порівнюють файлами:
  `git diff --no-index <a> <b>` чи хеш. Однакові — один елемент «копія в
  `<тека>`»; різні — перелік відмінностей короткими рядками (додано функцію,
  змінено параметр, інший хост). Схожість назви без порівняння копією не
  вважають.
- **Порядок запуску** — за числовим префіксом імені (`00-…`, `10-…`, `99-…`);
  префікс без ланцюжка в коді — «припущення».
- **Підключення** — хто кого підключає крапкою (розд. 2). Спільні файли
  (`00-common`, `00-config`) — елементи з переліком споживачів: зміна в них зачіпає
  кожного споживача.

## 11. Карта будови скрипта — не реалізовано

Карту будови скрипта (параметри, функції, регіони) пакет не будує. Якщо вона
знадобиться, її додають окремим режимом у `mindmap`: вузли дерева
`ParamBlockAst`, `FunctionDefinitionAst` і регіони з токенів коментарів; цей
файл — джерело переліку.
