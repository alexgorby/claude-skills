# Профіль проєкту для пакета письма документів

> Шаблон. Заповнений файл живе в проєкті; інструкції проєкту або його кореневий
> файл для агента вказують на нього одним рядком. Метадані файла — за конвенцією
> проєкту, не за цим шаблоном.
>
> Профіль нічого не визначає сам: у кожному слоті стоїть **адреса**, де вміст
> лежить у проєкті. Таблиця значень сюди копіюється тільки тоді, коли іншого
> місця в неї немає. Порожній слот — законний стан: пишеться «немає», а не вигадка.

## 10. Правила комунікації

Домовленості про листи, коментарі й задачі в трекері (`shared/genres/general.md`,
розд. 3, 7 і 8; дієслова дії над файлом — `shared/language.md`, 1.15). Слот
порожній чи рядка немає — діє типове правило пакета за адресою вище. Рядок пишуть, коли проєкт від типового правила відходить або
задає власну форму: звертання, склад опису задачі, формат назви.

| Питання | Як у проєкті |
|---|---|
| Звертання, коли отримувачів кілька, рахуючи копію | <наприклад, «Вітаю, колеги!» без імен> |
| Чи може лист бути першоджерелом факту | <за правилом пакета — ні; наприклад, так: листування із Замовником — частина договору, рішення фіксує лист> |
| Чи ставлять питання в коментарі трекера | <за правилом пакета — ні; наприклад, так: суміжні підрозділи читають трекер і відповідають у ньому> |
| Склад розділів опису задачі в трекері | <наприклад, «Мета, Вхідний стан, Виконання, Результат, Умова старту, Критерій виконання, Джерела; обов'язкові — Мета, Виконання, Критерій виконання»; або посилання на шаблон опису в проєкті> |
| Формат назви задачі | <наприклад, «<план> - <проєкт> - <назва>»; назва не повторює слів префікса> |
| Закріплені значення дієслів дії над файлом | <за правилом пакета — попередній стан називають прямо (`shared/language.md`, 1.15); наприклад: «записано» — файла в репозиторії не було, «перенесено» — там лежала попередня версія> |

## 12. Рецензія

Дані для скіла `review`. Порожній рядок — скіл питає власника, а не вигадує.

| Рядок | Що в ньому |
|---|---|
| Правила для рецензентів | які файли правил проєкту читають рецензенти (`review/SKILL.md`, крок 1) |
| Субагенти | лише Claude сесії чи можна сторонню модель (правило чутливості проєкту; крок 3) |
| Доменний експерт | агент проєкту й умова, коли його вмикати; немає — немає |
| Минулі уроки | де лежать пастки й уроки проєкту (`review-feasibility`) |
| Чи є чинна норма безпеки | так · ні · де лежить (`review-security`) |
| Базовий набір вимог | назви й шляхи джерел вимог або «немає» (`review-requirements`) |
| Документ | зміст, тека частин, вступна частина з правилами читання |
| Службові частини | що в частині не є тілом документа |
| Що поза обсягом, з причиною | перелік для брифу й звіту |
| Реєстри вже відомого | реєстри питань, погоджень, рішень; немає — «немає», і поле «Вже відоме» у знахідках тоді «не перевіряв» |
| Остання рецензія і реєстр її знахідок | дата й адреса |
| Джерело стану частини | що старше, коли джерела розходяться |
| Зони адресатів питань | хто відповідає за які теми |
| Схеми | чим їх читати |
| Куди пишеться звіт і під яким ім'ям | тека й шаблон імені |
| Вказівки кутам | на що в документах проєкту дивитись особливо |

Повний опис рядків — `skills/review/references/large-document.md`, розд. 1.
