# ADR — запис архітектурного рішення

Один документ — одне рішення. Поруч читати: `evidence.md`, `language.md`,
`../forks-and-questions.md`.

ADR пишуть, коли разом виконано три умови:

- рішення дорого змінити потім: воно зачіпає кілька компонентів, контракт між
  ними або дані, і відмова від нього вимагає переробки;
- без контексту воно неочевидне: читач без цього запису припустив би інше;
- за ним стоїть справжній компроміс між варіантами.

Найчастіше поріг проходять такі рішення: свідомий відхід від типового
налаштування чи рекомендації вендора; обмеження, якого не видно з конфігурації;
межа відповідальності між сторонами; відхилений варіант із неочевидною
причиною відмови. Такий запис не дає наступному інженерові «виправити»
навмисне.

Вибір, який легко переграти, і вибір, що прямо виводиться з документації
вендора, окремого ADR не потребують: це рядок рішення з компромісом у HLD
(`../forks-and-questions.md`, розд. 3). Поріг каже, коли ADR пропонувати, а не
коли відмовляти: на явний запит власника виконавець пише ADR завжди.

```markdown
# <Компонент або рішення>

## Контекст і вимоги
Що треба досягти. Обмеження. Нефункціональні вимоги з числами.

## Розглянуті варіанти
Таблиця: варіант / що дає / чого коштує технічно.

## Рішення
Що обрано. Безособово: «Обрано …», не «ми обрали».

## Обґрунтування
Чому саме це. Прив'язка до вимог із першого розділу.

## Компроміси
Що втрачається. Явно.

## Відкриті питання
Нерозв'язані конфлікти з адресатом і терміном.

## Наслідки
Що це змінює в інших компонентах. За якої умови рішення переглядають:
«переглянути, коли …».
```

Розділ **Компроміси** обов'язковий. Рішення без явних мінусів виглядає як реклама,
а не як архітектура.

Колонка вартості, ліцензій чи тарифів у таблицю варіантів не йде, якщо проєкт
тримає комерцію поза технічними документами: порівняння будується на технічних
наслідках.

Підстава — інженерний наслідок, не адреса сторінки (`hld.md`, розд. 4).
Альтернатива, винесена за обсяг робіт рівнем вище, у варіанти не повертається.

Рішення не видаляються: нове рішення перекриває старе й називає, яке саме замінює.

**Рішення поза ADR живе в тілі документа**, а не в окремому журналі. Запис або
самодостатній — рішення, відкинута альтернатива, причина одним рядком, — або
голий факт без причини. Наявність причини показує читачеві, чи рішення
зважувалось.

## Чек-лист ADR

- [ ] Одне рішення в документі
- [ ] ADR з власної ініціативи — лише коли разом виконано три умови порогу
- [ ] У «Наслідках» названо умову перегляду рішення
- [ ] Вимоги першого розділу мають числа
- [ ] Є розділ «Компроміси» з реальними втратами
- [ ] Обґрунтування прив'язане до вимог, а не до переваг варіанта взагалі
- [ ] Відкриті питання мають адресата
- [ ] Рішення сформульоване безособово
