# План

**Вмикається тільки за явним посилом власника.** Скіл планування не пропонує,
не нагадує про нього й не розгортає його сам. Якщо проєкт має власний формат
плану — старший він; цей файл несе ядро, що від формату не залежить.

Файл — друга хвиля пакета: ядро зафіксоване, розгортання буде після першого
застосування.

## 1. Порядок

План для плану → план → сама задача. Обмежена розвідка входу → п'ять рядків →
чекпойнт → повна робота. Повне читання входу до чекпойнта — помилка. Обмеження
розвідки залежить від типу входу: PDF — заголовки й вибіркові місця, довга
розшифровка — фрагменти й точки зміни теми.

## 2. План для плану

П'ять рядків:

1. Що читаю і в якому порядку.
2. Що витягую.
3. На що звіряю.
4. Який вигляд матиме результат.
5. Чого НЕ робитиму.

Рядки пишуться про конкретику, не про методику. Не «прочитаю, витягну, зведу»,
а «розшифровка десь сорок хвилин про розрахунок ресурсів, стикується з таблицею
від пресейлів, з'єднаю там».

Живе в розмові, у сховище не пишеться. «Пропускаємо» від власника знімає крок.

**П'ятий рядок розмову переживає.** Він переїжджає в «Не робимо» того розділу,
над яким іде робота, і формулюється наново перед кожним розділом. Решта чотири
рядки одноразові. Саме п'ятий рядок ловить зайву роботу, і саме його виконавець
порушує через три ходи.

## 3. Ядро плану задачі

- **Вхідні дані записані до початку роботи:** що хоче замовник — постановка
  дослівно — і критерії виконання.
- **Декомпозиція на кроки.** Форма — «крок · вихід · стан» плюс спосіб закриття.
- **Звіт у кожній сесії:** що з кроків виконано.
- **Новий крок додається тільки після обґрунтування,** що він впливає на основну
  задачу, а не є побічною роботою.
- **План звіряється з постановкою,** а не тільки з власною логікою: робота,
  яку призначив план, виглядає обов'язковою, навіть коли постановка її не просила.
- **Вихідний артефакт не з'являється раніше за дані,** з яких він виводиться.
- **Зміна постановки під час роботи — дельтою.** Зрушили обсяг, критерії
  виконання або з'явилась нова вхідна умова — план не переписується. До нього
  дописується блок «Дельта <дата>: що змінилось і чому», і переплановуються лише
  зачеплені кроки; решта погодженого плану лишається як є. Дельта показується
  власникові й чекає підтвердження, як п'ять рядків плану для плану (розд. 1).

## 4. Письмо плану

План пишеться тими самими правилами `language.md`, що й решта документів. Блоки
з'являються за наявністю вмісту, а не за шаблоном.

Критерій виконання — спостереження, залежне від виконавця. Чужа дія — погодження,
підпис — критерієм не є: це умова, і закриття вона не блокує.

Кожне ускладнення звіряється з фінішем: воно потрібне для цієї задачі чи для
гарної системи взагалі. Друге — стоп. Розширення обсягу оголошується,
а не питається «зробити краще?».

Дві взаємовиключні мети — не підзадачі, а альтернативні цілі — означають два
окремі плани. Рішення розділяти ухвалює власник: виконавець зупиняється
й оголошує альтернативу.

## Чек-лист плану

- [ ] Планування ввімкнено явним посилом власника
- [ ] Постановка й критерії записані до початку роботи
- [ ] Рядок «чого НЕ робитиму» конкретний і перенесений у «Не робимо» розділу
- [ ] Критерій виконання не впирається в чужу дію
- [ ] Кожен новий крок має обґрунтування впливу на основну задачу
- [ ] Зміна постановки дописана дельтою з датою; погоджений план не переписано
