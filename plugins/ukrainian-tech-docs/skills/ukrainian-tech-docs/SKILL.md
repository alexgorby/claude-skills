# Диспетчер пакета технічної документації

Пакет ділиться на шість скілів, кожен робить одну задачу. Цей файл каже, який
скіл узяти і які правила діють між скілами. Зміст правил лежить у скілах і в
спільній теці `shared/`.

## 1. Задача → скіл

| Задача | Скіл | Коли |
|---|---|---|
| Пишеться або правиться зміст документа | `write` | новий документ, розділ, правка змісту, «переписати документ» (зміст чи будова), «оформити як нотатку», переклад, схема до документа, питання до суміжників |
| Перевірка мови й аудит готового тексту | `language` | «перевір мову», «почистити текст», «прибрати воду» (чистка мови без зміни змісту), «діагностика кальок», «перевір переклад», аудит чужого документа без правки, «перевір ТЗ» — зокрема на виконуваність |
| Звірка тверджень із джерелами | `factcheck` | «фактчекінг», «перевір факти», «звір із документацією», «чи це досі так» |
| Документ іде назовні | `export` | `.docx`, `.xlsx`, `.pdf`, лист, повідомлення поза командою |
| План роботи | `plan` | лише за явним посилом власника |
| Незалежна рецензія плану чи документа | `review` | «план готовий», «перевір незалежно», «рецензія HLD», «рецензія ТЗ», «тест читача» |

Неоднозначні запити розводяться так:

| Запит | Скіл | Чому |
|---|---|---|
| «переписати документ» без уточнення, чи змінюється зміст | `write` | він охоплює і чистку мови |
| «почистити текст», «прибрати воду» | `language` | чистка мови без зміни змісту; щойно вона зачіпає твердження чи будову — `write` (розд. 2) |
| «перевір ТЗ» | `language`, «Аудит ТЗ» | прохід передачі й чек-лист жанру; `review` — лише на «рецензія ТЗ» чи «перевір незалежно» |
| «почисти текст», «тест читача», «чи звучить це як ШІ» без типу тексту | за самим текстом | технічний документ, нотатка, інструкція — цей пакет; глава, сцена, діалог, художня проза — `ukrainian-fiction`. З тексту не видно — одне питання власникові |
| «план готовий», а плану в розмові немає | `review` | скіл питає, де план (файл чи текст), і без нього не починає |
| «перевір мову і факти» | `factcheck` → `language` | обидва без правки тексту, два звіти поруч; правка за знахідками — `write` |
| Документ іде Замовнику | `write` → (`factcheck`) → `export` | `review` сам не вмикається; якщо рецензії документа ще не було, запропонувати її одним рядком |

Скіл викликається інструментом виклику скіла з повним іменем:
`ukrainian-tech-docs:write`, `ukrainian-tech-docs:language` тощо. Там, де
виклику скіла немає, — прочитати `SKILL.md` потрібного скіла з теки
`skills/<скіл>/` плагіна.

## 2. Правила між скілами

Ці правила не належать жодному скілу окремо. Кожен скіл, що править текст, ще й
несе їх у своїх передумовах, тож вони діють і без диспетчера.

- **Зміст змінюється — письмо й самоперевірка обов'язкові**, хоч би яку задачу
  названо в запиті. Вивантаження, під час якого переписано зміст, аудит із
  правкою змісту, фактчекінг, за яким правиться текст, — це ще й `write`.
- **Чистка мови без зміни змісту — лише `language`.** Слова, звороти, кальки,
  вода: твердження, суб'єкт дії і будова лишаються ті самі. Тоді `write` не
  потрібен, а самоперевірку дають передумови `language`: фінальний прохід і
  «Переписування зберігає зміст». Щойно чистка зачіпає твердження, суб'єкт дії
  чи сусідній абзац — це вже `write`. Межа та сама, що в «Дрібній правці»
  (`write/SKILL.md`, розд. 1).
- **Вивантаження в `.docx`, `.xlsx`, `.pdf` іде після повного мовного проходу
  по остаточному тексту**: частини 1 і 2 `shared/language.md` і діагностика
  кальок. Прохід — останній крок перед збіркою, а не перший крок вивантаження.
- **Закривальний рядок і підсумок маркерів — один на всю роботу**
  (`write/SKILL.md`, розд. 3). Кожен скіл, що працював, додає до рядка свою
  частину. Стадії, якої в рядку немає, не пройдено, і слово «готово» не
  пишеться.
- **Планування не вмикається саме.** Лише за явним посилом власника.
- **Порядок для типової роботи**: `write` → (`factcheck`, якщо просили) →
  `export`. Рецензія `review` — на готовий документ, перед тим як він іде в
  роботу.

## 3. Закривальний рядок у кожному скілі

Правило рядка й підсумку маркерів — `write/SKILL.md`, розд. 3. Рядок пише
кожен скіл, а в роботі з кількох скілів рядок один і збирає їхні частини.
У рядку стоять файли, які справді прочитано, а не назви стадій.

| Скіл | Зразок рядка |
|---|---|
| `write` | `Стадії: вхід (write/SKILL, профіль, genres/hld, genres/general) · письмо (evidence, language) · самоперевірка (чек-лист hld, фінальний прохід, evidence розд. 7, реєстр кодів, словник)` |
| `language` | `Стадії: аудит мови (language/SKILL, language: Аудит, Вага ознак, Діагностика кальок; профіль: словник) · текст не змінювався` |
| `factcheck` | `Стадії: фактчекінг (factcheck/SKILL, factcheck, evidence розд. 1–3; профіль: сходи джерел) · текст не змінювався` |
| `export` | `Стадії: вивантаження (export/SKILL, export, профіль вивантаження з проєкту) · мовний прохід по остаточному тексту (language: частини 1–2, Діагностика кальок, Фінальний прохід) · збірка (.docx)` |
| `plan` | `Стадії: планування (plan/SKILL, genres/plan, genres/general) · самоперевірка (чек-лист плану, фінальний прохід)` |
| `review` | `Стадії: рецензія документа (review/SKILL, roster, review-contract, document, consolidation, report) · режим: з субагентами · кути (УЗГ, ЗДС, БЕЗ) · опонент (review-verifier) · текст не змінювався` |

**Профілю немає** — рядок каже це словами: `профіль: немає`.

**Звірка рядка.** У `write` рядок звіряється з рядком «Стадії» контракту.
У скілах без контракту (`language`, `factcheck`, `review`) — з тим, що скіл
велить пройти (`language` і `factcheck` — розд. 1, `review` — кроки 1–6): пропущений крок або пройти, або назвати
причину.

**Підсумок маркерів** іде поруч із рядком у кожному скілі. Скіл, що текст не
править, маркерів не ставить і пише «маркерів не ставив».

## 4. Де лежать файли

Шляхи в усіх файлах пакета короткі: `language.md`, `genres/hld.md`. Повна
адреса — від кореня плагіна:

| Файл | Де |
|---|---|
| `language.md`, `evidence.md`, `genres/*.md`, `templates/project-profile.md` | `shared/` |
| `forks-and-questions.md`, `postmortem/*.md`, шаблони постмортему | `skills/write/references/`, `skills/write/templates/` |
| `factcheck.md` | `skills/factcheck/references/` |
| `export.md`, `templates/export-profile.md` | `skills/export/references/`, `skills/export/templates/` |
| файли рецензії | `skills/review/references/`, `skills/review/scripts/`, агенти — `agents/` |

Від теки будь-якого скіла `shared/` — це `../../shared/`. Посилання виду
«`write/SKILL.md`, розд. 1» ведуть у `skills/write/SKILL.md`.

## 5. Чого пакет не робить

- Не визначає метаданих: frontmatter, теги, статуси, нумерацію — це конвенція
  проєкту.
- Не пропонує планування і не вмикає його сам.
- Не тримає даних проєкту: імен джерел, кодів, палітр, адрес. Приклади у
  файлах — приклади.
- Не застосовується до художніх текстів.

Джерела ідей пакета — `SOURCES.md` у корені плагіна.
