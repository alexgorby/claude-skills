# Оновити документи після зміни скриптів

Режим скіла `write`: скрипти змінились, і треба знати, які документи й розділи
перевірити та що в них, найімовірніше, змінити. Виділення залежностей —
`../../../shared/powershell.md` від теки цього файла. Скриптів не запускають.

## 1. Обсяг змін — явний

Спершу назвати, що із чим порівнюють, і лише потім читати зміни:

| Що порівнюють | Як |
|---|---|
| Коміт проти коміту, тег проти тегу | `git diff <було>..<стало> -- <шлях>` |
| Гілка проти основної | `git diff <основна>...<гілка>` |
| Робоче дерево | окремо індексоване (`git diff --cached`), неіндексоване (`git diff`) і нові файли (`git status --porcelain`, рядки `??`) |

Робоче дерево не підміняють останнім комітом, а неіндексовані зміни — комітом.
Власник не назвав, що порівнювати, — береться одне з таблиці, і звіт першим
рядком каже, що саме взято. Обсяг стоїть у звіті числами: скільки файлів,
скільки рядків додано й прибрано.

## 2. Що змінилось у коді

З різниці й дерева розбору обох версій (`shared/powershell.md`, розд. 1) —
перелік змін за класами таблиці розд. 3. Для кожної зміни — файл і рядок у
новій версії. Опис коміту — підказка, а не джерело: клас зміни визначає код.

## 3. Зміна → документи

Таблиця дає кандидатів. Вона не доводить, що документ треба правити: перед
висновком дивляться саму зміну й саме місце документа.

| Зміна в коді | Що перевірити в документах |
|---|---|
| Новий командлет іншого модуля — нова система (`shared/powershell.md`, розд. 3–4) | Розділи залежностей HLD і LLD; передумови модулів і прав у процедурі |
| Новий ресурс у хмарі (створення через модуль чи REST) | LLD: ресурс, ім'я, параметри; HLD: компонент і його зв'язки; процедура: права на створення |
| Змінено параметр: додано, прибрано, нове допустиме значення | Кроки процедури, де його задають; довідник параметрів |
| Додано, прибрано чи переставлено скрипт у ланцюжку | Чек-лист послідовності; порядок кроків процедури. Номер у назві й порядок запуску можуть розходитися — порядок беруть з оркестратора, а не з імен |
| Змінено спільний файл (`00-common`, `00-config`, бібліотека в `common`) | Документи кожного споживача файла (`shared/powershell.md`, розд. 10) |
| Новий ключ конфігурації чи змінено його значення за замовчуванням | Довідник конфігурації; приклади конфігу в процедурі |
| З'явились `Remove-*`, `Set-*`, `-Force` чи інша дія, що змінює стан | Попередження і відкат у процедурі |
| Змінено віддалену ціль (`-ComputerName`, `Invoke-Command`, сеанс) | Мережеві передумови: WinRM, брандмауер, порти |
| Змінено перевірку (`verify`, тести) | Розділ перевірки процедури; критерії приймання |
| Змінено вивід, коди виходу, журнали | Troubleshooting і runbook: як розпізнати збій |

Зміна, якої немає в жодному документі, — теж знахідка: «не описано», з тим,
який документ мав би її нести.

## 4. Де шукати документи

Теки документів дає профіль проєкту (`write/SKILL.md`, розд. 2). У документах
шукають назви змінених скриптів, параметрів, ключів конфігурації, ресурсів і
кроків ланцюжка. Документ без прямої згадки, але з розділом про ту саму
систему (залежності HLD, передумови процедури), теж кандидат.

## 5. Результат

Таблиця по документах:

| Документ · місце | Що змінилось у коді (файл:рядок) | Що, найімовірніше, змінити | Стан |
|---|---|---|---|

Стан має три значення: «треба» — документ прямо суперечить новому коду; «перевірити» — місце
зачеплене, але чи суперечить, з коду не видно; «не зачеплено» — розглянуто й
відкинуто, з причиною.

Під таблицею — обсяг змін (розд. 1), що не перевірено (скажімо, документи поза
названими теками) і чого скрипти не запускали.

Документи правлять лише на прохання; тоді — за правилами жанру кожного документа й звітом про зміну (`write/SKILL.md`, розд. 3). Без прохання
результат — таблиця кандидатів.

## Чек-лист

- [ ] Названо, що із чим порівнювали; обсяг змін — числами
- [ ] Робоче дерево розкладено на індексоване, неіндексоване й нові файли, якщо порівнювали його
- [ ] Кожна зміна має файл і рядок нової версії; клас визначено з коду, а не з опису коміту
- [ ] Спільні файли — з усіма споживачами
- [ ] Порядок ланцюжка взято з оркестратора, а не з номерів у назвах
- [ ] Кожен рядок таблиці має стан; «не зачеплено» — з причиною; незадокументоване — «не описано»
- [ ] Документи без прохання не правили; скриптів не запускали
