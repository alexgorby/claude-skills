# Вивантаження назовні

Порядок вивантаження лежить у `references/export.md`. Профіль вивантаження
конкретного файла заповнюється за `templates/export-profile.md`. Правила мови —
у `../../shared/language.md` від теки цього скіла.

## 1. Порядок

1. **Вхід.** Профіль проєкту (`write/SKILL.md`, розд. 2) і профіль
   вивантаження з проєкту, якщо він є. Прочитати `references/export.md`.
2. **Зміна змісту.** Якщо вивантаження змінює зміст, а не лише форму, —
   це ще й письмо: правила `write` за `evidence.md` і жанровим файлом,
   самоперевірка. Маркери `[на погодження]` розкриваються за `export.md`,
   розд. 4.
3. **Підготовка форми** за `export.md`: посилання, таблиці, схеми, профіль.
4. **Мовний прохід — останній крок перед збіркою.** Після всіх правок цього
   вивантаження прочитати `language.md`, розділи «Діагностика кальок» і
   «Фінальний прохід», і пройти остаточний текст. Для `.docx`, `.xlsx`, `.pdf`
   прохід іде по всіх пунктах частин 1 і 2 (`export.md`, розд. 0). Прохід перед
   правками, зробленими пізніше, не зараховується.
5. **Збірка** файла.
6. **Закривальний рядок і підсумок маркерів** за
   `../ukrainian-tech-docs/SKILL.md`, розд. 3, з переліками перед записом
   назовні: `Стадії: вивантаження (export/SKILL, export; профіль вивантаження: немає) · мовний прохід по остаточному тексту (language: частини 1–2, Діагностика кальок, Фінальний прохід) · збірка (.docx)`.
   Запис назовні чекає відповіді на підсумок маркерів.

## 2. Захист від пропуску

У Claude Code хук плагіна перевіряє наприкінці ходу: якщо створено чи змінено
`.docx`, `.xlsx` чи `.pdf`, а після останньої зміни тексту мовного проходу не
було, хід не завершується. Хук ловить пропуск, але не доводить, що прохід
виконано якісно, тож закривальний рядок обов'язковий і з хуком.
