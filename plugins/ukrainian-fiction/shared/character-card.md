# Картка персонажа

Читати скілу `setup`, коли він створює чи перевіряє картку, і скілу `write`,
коли в сцені говорять герої з картками. Шаблон — `templates/character-card.md`;
де лежать картки книги, каже слот профілю «Персонажі» (`profile.md`).
Пункти Ч1–Ч8; нумерація стабільна.

## Ч1. Формат

Картка — Markdown-файл: короткі поля на початку файла (frontmatter), далі
розділи з назвами із Ч3. Тип картки один для всіх героїв: головний герой і
епізодичний мають той самий шаблон, у другорядного просто більше порожніх
розділів.

**Картку не скорочувати й не обмежувати.** Розділ може бути порожнім чи в одне
речення, а може бути на сторінку. Довжина картки — справа автора, а не скіла.

## Ч2. Поля на початку файла

У поля йде все коротке й стале: те, що не міняється від глави до глави.

| Поле | Що там | Обов'язкове |
|---|---|---|
| `type: character` | Ознака картки | так |
| `status` | `канон` або `задум` | так |
| `role` | Роль в історії | так |
| `aliases` | Інші імена й звертання | ні |
| `species` | Вид, раса; для людей можна не заповнювати | ні |
| `state_as_of` | На який момент історії описано героя | так |
| `age`, `gender`, `height`, `origin`, `title` | Вік, стать, ріст, місце походження, звання — те, що в книзі стале | ні |

Поля книги (свої для кожної книги) дозволені; профіль книги може їх
перелічити. **Змінне від глави — не в полях.** Ранг, рівень, поранення, нові
речі пишуться в розділ «Зміни по главах», рядком на главу: «гл. 02 — рівень 10»,
«гл. 03 — рівень 11, поранено ліве плече». Так видно, яким герой був у кожній
главі, а поле не застаріває непомітно.

## Ч3. Розділи

Назви й порядок — за таблицею. Колонка «Симуляція» позначає розділи, з яких
збирається роль героя для розмови агентів (`роль`); «Безперервність» —
розділи, за якими звіряють, що герой не змінився між главами без причини.
Звірку між главами робить `continuity` (Б1–Б4): за колонкою «Безперервність»
він читає ці розділи. Розмови агентів у пакеті ще немає: колонка «Симуляція»
готує картку наперед і нічого не вимагає.

| Розділ | Що там | Симуляція | Безперервність | Обов'язковий | Синоніми |
|---|---|---|---|---|---|
| Коротко | Хто це, одним-трьома реченнями | роль | | так | «Суть» |
| Як думає | Як герой міркує, на що зважає, де помиляється | роль | | ні | |
| Епізоди | Два-три випадки із життя героя; кожен позначено «факт» (є в книзі) чи «думка» (задум автора) | роль | | ні | |
| Як говорить | Звороти, що повторюються; чого уникає в мові; свідомі відступи від норми; підрозділи «Звертання» (як герой звертається до інших і як до нього, і чи це міняється з главами) і «Зразки реплік» (Ч7) | роль | | так | «Голос», «Як писати», «Мова» |
| Характер | Недоліки, поведінка (що робить руками, як реагує на загрозу), протиріччя | роль | | ні | «Портрет» — частково |
| Чого хоче · що приховує · чого боїться | Мета героя, таємниця, страх; що любить і чого не терпить; підрозділ «Правда й брехня» — чи бреше герой, коли і як (прямо, недомовкою, мовчанням) | роль | | ні; для симуляції — так | |
| Що знає | Що герой знає до книги або на момент `state_as_of` | роль | | ні; для симуляції — так | |
| Побут | Звички, їжа, житло, гроші | роль | | ні | |
| Зовнішність | Підрозділ «Одяг і прикмети» | | так | ні | «Портрет» — частково |
| Передісторія | Підрозділ «Місце походження» | | так | ні | «Минуле» |
| Уміння | Що герой уміє і чого не вміє — там, де вміння героїв різні; бажано з джерелом факту (Ч5) | | так | ні | |
| Зміни по главах | Ранг, рівень, поранення, речі — рядком на главу (Ч2), бажано з джерелом факту (Ч5) | роль — рядки до глави сцени | так | ні | |
| Зв'язки | Стосунки з іншими героями; близькість — там, де книга цього потребує | роль | так | так | «Стосунки» |
| У главах | Де герой з'являється | | так | так | «Де з'являється» |
| Відкрите | Що автор про героя ще не вирішив | | | ні | |
| Звідки образ | Що взято із чужої картки, книги чи реальної людини, а що свідомо ні | | | ні | |
| Журнал рішень | Дата, що вирішено, слова автора (Ч5) | | | ні | |

**Синоніми.** Розділ з іншою назвою з колонки «Синоніми» — той самий розділ.
Перевірка (Ч6) підказує канонічну назву, але не вимагає її. «Портрет», що
вміщає і вигляд, і вдачу, — підказати поділ на «Зовнішність» і «Характер».

## Ч4. Що з картки бере `write`

Коли в сцені говорять герої з картками, `write` на вході читає в картці
кожного з них:

- «Коротко»;
- «Як говорить» разом зі «Звертанням» і «Зразками реплік»;
- «Чого хоче · що приховує · чого боїться» з «Правдою й брехнею» — для
  підтексту репліки (Д2);
- «Зміни по главах» — лише рядки до глави, яку пише. Главу сцени не
  названо — взяти главу з `state_as_of` і сказати це вголос або спитати
  автора, якщо від цього залежить сцена.

Картки немає чи потрібний розділ порожній — `write` не зупиняється: пише за
каноном голосу книги й говорить про це вголос («картки Н. немає — голос за
каноном книги»). Картка й канон голосу книги розходяться (герой у картці
говорить інакше, ніж каже канон) — показати обидва місця і спитати автора,
а не вибирати мовчки (`profile.md`, «Старшинство»).

**Зразки реплік — зразок голосу, а не заготовки.** У сцену вони не
переносяться ні як репліки, ні як чужі думки, спогади чи очікування героя:
нова репліка звучить тим самим голосом, але іншими словами.

**Рису мови не обходять.** Звертання, зворот чи відступ від норми, записаний
у картці, звучить там, де героєві природно його вжити. Сцена не будується
так, щоб приводу для риси не було, і риса не стоїть у кожній репліці.

## Ч5. Рішення автора в картці

Рішення автора про героя вливається у свій розділ як факт: «боїться
висоти», а не «2026-10-18: вирішено, що боїться висоти». Дата й слова автора
пишуться рядком у «Журнал рішень» наприкінці картки. Так картку читають як
опис героя, а історію рішень видно окремо.

**Скасоване не стоїть поруч із поправкою.** Рішення, яке автор скасував,
замінив чи визнав хибним, прибирається з розділу, а не лишається поряд із
реченням, що його виправляє. Поправку можуть не прочитати ні людина, ні
модель, що збирає з картки роль героя, і тоді в роботу піде старе. У
розділі лишається лише чинне; що було й що стало, з датою, — рядком у
«Журнал рішень». Дата в журналі — дата рішення автора. Її в картці немає —
місце лишається порожнім із позначкою «дата невідома» або дату питають в
автора; дату перевірки чи переведення на її місце не ставлять. Інші ноти
книги авторові варто вести так само: старе — у розділ «Зміни» наприкінці, а
не поруч із новим.

**Джерело факту.** Факт, який можна звірити (уміння, рівень, поранення, річ),
бажано позначати джерелом: «гл. 04», «гл. 04, р. 112», назва ноти канону.
Позначка не обов'язкова, але без неї суперечність між карткою і главою
доводиться шукати по всій книзі.

## Ч6. Перевірка картки

На прохання «перевір картку» скіл `setup` звіряє картку із Ч1–Ч5 і повертає
знахідки таблицею. Картку він не править: що змінити, вирішує автор.

| Розділ чи поле | Що не так | Пропозиція |
|---|---|---|

Що шукати:

1. Бракує обов'язкового поля чи розділу (Ч2, Ч3).
2. Розділ під синонімом — підказати канонічну назву; це не вада, а підказка.
3. Змінне від глави (ранг, рівень, поранення) стоїть у полях — запропонувати
   перенести в «Зміни по главах».
4. Датовані заголовки посеред картки («Рішення автора <дата>») — запропонувати
   влити рішення в розділ і перенести дату й слова в «Журнал рішень» (Ч5).
5. Матеріал не про героя (сюжет, устрій світу, чужі таємниці) — кандидат на
   винесення в окрему ноту з посиланням із картки. Рішення за автором.
   Сюжетна лінія, у якій герой лише одна з ланок, — теж матеріал не про
   героя, навіть коли починається з його вчинку чи записана в «Епізодах»
   або «Зв'язках». Сам учинок героя, з якого лінія почалася, — його епізод
   і лишається в картці; кандидат на винесення — те, що сталося далі без
   нього. Після винесення (рішення за автором) у картці лишаються учинок,
   те, що лінія змінила в самому героєві (факт у своєму розділі чи рядок
   «Зміни по главах»), і посилання на ноту лінії. До рішення лінія стоїть у
   картці з позначкою кандидата.
6. Порожні «Як говорить» чи «Чого хоче» — підказка на майбутнє, а не вада:
   розмови агентів за такою карткою не буде, коли пакет її матиме.
7. Скасоване рішення поруч із поправкою (Ч5). Ознака — суперечність, а не
   слово: нове твердження виключає старе («сорок років» і «йому тридцять
   п'ять»). Позначки бувають різні, наприклад закреслений текст `~~…~~`,
   «попередня редакція», «до того стояло», «замінює редакцію», «уточнення:
   …» поряд зі старим твердженням, та інші позначки старої редакції.
   Уточнення, що лише доповнює чинне («шрам на щоці; уточнення: на лівій»),
   — не знахідка; за сумніву — питання авторові. Запропонувати лишити в
   розділі чинне, а старе перенести в «Журнал рішень» з датою рішення (Ч5).

Зміст картки — канон автора: скіл не оцінює, чи вдало придуманий герой, і не
пропонує йому нових рис.

## Ч7. Зразки реплік

Три-п'ять реплік героя в різних обставинах. Кожна позначена джерелом:

| Позначка | Звідки |
|---|---|
| `з глави NN` | Справжня репліка з написаної глави |
| `промпт для реплік, <модель>, погоджено <дата>` | Автор вибрав із відповідей сторонніх моделей (Ч8) |

Справжні репліки з глав згодом замінюють решту. Записує зразок у картку лише
автор або скіл за його згодою; придуманих скілом реплік без вибору автора в
картці немає.

## Ч8. Промпт для реплік

Коли в сцені говорять герої з картками, `write` пропонує авторові **промпт
для реплік**: самодостатній текст, який автор сам вставляє в різні мовні
моделі (ChatGPT, Gemini, Claude, інші, і різні моделі одного постачальника),
щоб вибрати фрази, які йому найбільше сподобаються.

**Коли пропонує.** Один раз за розмову, коротким рядком у першій відповіді,
де пишеться діалог героя з карткою; далі — на прохання «дай промпт для
реплік». Пропозиція не повторюється в кожній сцені.

**Два види.** Промпт **під сцену** дає ситуацію з каркаса й просить репліки
для неї. Промпт **для зразків голосу** дає кілька тем, і кожна ставить
героя в обставину, де виявляється одна риса з картки: побут, недомовка,
глузування, наказ, ставлення до третього героя. Відповіді на нього
поповнюють «Зразки реплік» (Ч7). Обидва види — за тим самим шаблоном; у
шаблоні є вигаданий заповнений приклад другого виду. Приклад показує, як
можна, а не як треба: форму автор міняє під книгу.

**Що в промпті.** Збирається за шаблоном `templates/replica-prompt.md`:

- з картки героя — розділи із Ч4;
- співрозмовник — одним-двома реченнями з його «Коротко», і хто з них
  сильніший чи вищий за становищем: від цього залежить, що герой може
  сказати вголос; у промпті для зразків голосу співрозмовників може бути
  кілька — по рядку на кожного, хто є в темах;
- ситуація — з каркаса автора: де, що щойно сталося, чого герой хоче в цій
  розмові;
- канон голосу й словник книги — у тій частині, що стосується реплік;
- що герой приховує — з тією межею розкриття, яку дає картка: «вголос не
  скаже» за замовчуванням, «ні прямо, ні натяком» — лише якщо так каже
  картка чи автор; підтекст дозволений;
- межа ролі — чого герой у своєму становищі сказати не може (наприклад,
  звинуватити старшого прямо), якщо картка чи каркас це кажуть;
- завдання: кілька варіантів кожної потрібної репліки, різних за тоном, живою
  українською, без пояснення почуттів.

**Без готових відповідей.** «Зразки реплік» і приклади фраз із картки
(«каже щось на кшталт „…“») моделі дослівно повторюють, і позначка «не
повторювати» цього не гарантує. Тому в промпт не йдуть ні «Зразки реплік»,
ні приклади фраз: прийом описується словами. Зразки лишаються в картці для
самого `write` (Ч4). Пряма вимога не повторювати формулювань промпту — у
самому шаблоні.

**Нічого понад картку.** Перед показом звірити: кожен факт промпту є в картці
героя, у каркасі чи в каноні голосу. Чого там немає (вік, зовнішність,
минуле), у промпт не дописується.

У промпт не йдуть задум автора, майбутні події, канон світу понад потрібне
для сцени. Скіл показує промпт цілком, щоб автор бачив, що віддає.

**Куди віддавати, вирішує автор.** Промпт запускає сам автор, тож рядок
профілю «Стороння модель» його не забороняє: той рядок стосується запусків,
які робить скіл. Якщо в профілі стоїть «не можна», у пропозиції сказати, що
промпт містить неопублікований текст.

**Порівняння відповідей.** Автор приніс відповіді кількох моделей — `write`
зводить їх таблицею:

| Тема | Модель | Репліка | Що видно |
|---|---|---|---|

У колонці «Що видно» — лише перевірне:

- дослівний чи майже дослівний повтор зразка з картки чи фрази з промпту —
  зразок стане повтором у книзі;
- риса мови в кожній репліці;
- суперечність із картки: зі «Звертанням», із «чого уникає», з «Правдою й
  брехнею»;
- приховане сказано вголос — чи натяком, якщо картка забороняє і натяк;
- факт, якого немає ні в картці, ні в каркасі, ні в промпті;
- вихід за межу ролі, якщо картка чи каркас її називають;
- кальки й ознаки ШІ з номером пункту.

Справна репліка лишається без позначок; сумнів до неї не дописується.
Найсильніший варіант не призначається: вибирає автор.

**Що далі з вибраними фразами.** Фрази, які автор приніс, — його матеріал.
`write` ставить їх у сцену й проходить звичайне письмо й самоперевірку:
відповідь сторонньої моделі може мати кальки й ознаки ШІ (`calques.md`,
`final-pass.md`, А5). Кожну зміну вибраної фрази показати «було · стало ·
пункт». Записати фразу в «Зразки реплік» — лише з погодження автора, з
позначкою із Ч7.
