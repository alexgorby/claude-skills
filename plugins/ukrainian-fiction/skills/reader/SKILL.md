# Читацький тест

Скіл дає главу читачеві, який знає лише текст, і звіряє, що той виніс.
Порядок тесту лежить у `references/reader-test.md` цього скіла (А6); там же
форма рядка таблиці знахідок (А6, п. 4).

## 1. Передумови

**Профіль книги — лише виконавцю.** Профіль і нотатки потрібні виконавцеві,
щоб скласти перелік «що читач мав винести» (А6, п. 1). Знайти профіль так,
як описано у `write/SKILL.md`, розд. 2. Читач профілю не отримує.

**Текст не змінюється.** Тест повертає знахідки. Що правити, вирішує автор;
правка — задача `write`.

## 2. Читач

Читач — агент `fiction-reader` цього плагіна (`agents/fiction-reader.md`).
Текст глави, а для не першої глави — попередні глави чи їхній переказ,
передаються в самому завданні агентові, як вимагає А6, п. 2.

**Агент бачить контекст теки, з якої запущено сесію.** Інструментів читання
файлів в агента немає, але Claude Code сам підкладає йому на старті
кореневий файл проєкту (`CLAUDE.md`) теки сесії з його імпортами. Якщо сесія
відкрита в теці книги, читач отримує канон ще до першого слова глави, і
«свіжість» порушено. Звіт тоді каже про це першим рядком.

**Агентів немає** (звичайний чат) — тест іде в тій самій розмові з позначкою
«не незалежний» у першому рядку звіту: читач, який бачив розмову, не свіжий.

## 3. Стадія → файл

| Стадія | Коли | Читати |
|---|---|---|
| Читацький тест | «тест читача», «чи зрозуміло це без мене», «як це прочитає людина з вулиці»; сам не вмикається; нічого не править | `reader-test.md`, А6 |

## 4. Закривальний рядок

`Стадії: читацький тест (reader/SKILL, reader-test А6) · читач: агент fiction-reader · текст не змінювався`

Якщо читач — не агент, рядок це називає: `читач: та сама розмова, не незалежний`.
Робота з кількох скілів пакета має один рядок на всю роботу (диспетчер,
розд. 3).
