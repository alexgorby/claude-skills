# Скіли Claude для українського письма

**Українська** · [English](README.en.md)

Два скіли для Claude, які допомагають писати українською так, щоб текст не
був схожий на переклад чи на згенерований машиною: без кальок, канцеляриту й
ШІ-кліше. Кожен скіл — окремий плагін, тож можна встановити один або обидва.

| Плагін | Для чого |
|---|---|
| `ukrainian-tech-docs` | Технічна документація — диспетчер і шість скілів: письмо, перевірка мови, фактчекінг, вивантаження, планування, мультиагентна рецензія. Контракт роботи перед письмом, дисципліна джерел і маркерів невизначеності, жива мова, жанрові правила (HLD, LLD, ADR, ТЗ, how-to і runbook, concept, reference, troubleshooting, постмортем, схема, план), питання до суміжних команд, вивантаження в .docx, .xlsx, .pdf чи лист. Що дати на вхід — [docs/ukrainian-tech-docs-inputs.md](docs/ukrainian-tech-docs-inputs.md); що таке кожен жанр і як його попросити — [docs/ukrainian-tech-docs-genres.md](docs/ukrainian-tech-docs-genres.md) |
| `ukrainian-fiction` | Художня проза: мова без кальок і ШІ-кліше, правопис і милозвучність, речення і абзац, діалог, будова сцени й глави, аудит готового тексту. Годиться і для перевірки вже написаного тексту — власного чи згенерованого. Правила конкретної книги (герої, словник, лор, тон) скіл не тримає — їх має давати профіль книги |

## Що вміє

Скіл вмикається сам, коли запит схожий на один із наведених. Формулювання
не обов'язково повторювати дослівно.

### ukrainian-tech-docs

Пакет має шість скілів, кожен робить одну задачу. Запит на кілька задач одразу
(«підготуй документ для Замовника») розводить диспетчер: каже, які скіли
потрібні та в якому порядку.

| Що зробити | Як попросити | Скіл |
|---|---|---|
| Написати документ потрібного жанру | «Напиши ADR про вибір …», «покрокова інструкція для …», «ТЗ на …» | `write` |
| Переписати документ, оформити нотатку | «Перепиши документ», «оформи як нотатку» | `write` |
| Перекласти технічний текст | «Переклади українською» | `write` |
| Сформулювати питання до суміжної команди | «Сформулюй питання до мережевиків про …» | `write` |
| Почистити текст від ШІ-кліше, канцеляриту й кальок, не чіпаючи змісту | «Почисти текст», «прибери воду» | `language` |
| Знайти кальки, нічого не правлячи | «Діагностика кальок», «перевір переклад» | `language` |
| Перевірити готове ТЗ | «Перевір ТЗ» | `language` |
| Звірити твердження з документацією | «Фактчекінг», «перевір факти», «звір із документацією» | `factcheck` |
| Зібрати файл для читача поза командою | «Збери docx», «оформи як лист» | `export` |
| Скласти план роботи | «Спершу план», «склади план» | `plan` |
| Незалежно перевірити план чи документ | «План готовий», «перевір незалежно», «рецензія HLD» | `review` |
| Перевірити, чи зрозуміло без автора | «Тест читача», «чи зрозуміло це без мене» | `review` |

Рецензія `review` дає план чи документ кільком вузьким рецензентам-агентам:
узгодженість, здійсненність, опонент рішень, безпека, архітектура, мережа
тощо. Рецензентів вибирає окремий агент-координатор, і кожен бачить лише сам
предмет, а не розмову, у якій його склали. Знахідки щодо документа ще перевіряє
опонент, головна сесія звіряє кожну з джерелом. Де субагентів немає, рецензія
йде в одній сесії і позначається як «не незалежна».

**Жанри.** Для кожного — свої правила будови й власний чек-лист.

| Жанр | Що в ньому |
|---|---|
| HLD | Концепції, рішення, компроміси, без значень конкретної збірки |
| LLD | Значення, адреси, параметри й порядок кроків як наслідок рішень HLD |
| ADR | Одне архітектурне рішення з варіантами й компромісом |
| ТЗ | Що потрібно і як це приймають: лише виконувані пункти, без відкритих питань |
| How-to, runbook, процедура | Кроки з перевіркою та відкатом |
| Покрокова інструкція | Лише дії для читача, який їх ще не виконував: пререквізити з перевіркою, крок за кроком |
| Concept | Як працює компонент |
| Reference | Таблиці, схеми даних, коди, без прози |
| Troubleshooting | Запис випадку, симптом першим |
| Постмортем | Закриття інциденту після відновлення сервісу |
| Безпековий документ | Як система захищена: доступ, секрети, мережева поверхня, дані, ланцюг постачання |
| Схема | Топологія і механізм, читаність у друці |
| План | Лише коли попросите: «спершу план», «склади план» |
| Лист, повідомлення, нотатка, README | Загальні правила: один документ — одне завдання; лист — зріз робочого документа для одного адресата |

Докладно про кожен жанр і як його попросити —
[docs/ukrainian-tech-docs-genres.md](docs/ukrainian-tech-docs-genres.md).

### ukrainian-fiction

| Що зробити | Як попросити |
|---|---|
| Написати сцену чи главу | «Напиши сцену …», «для наступної глави …» |
| Почистити главу від ШІ-кліше | «Почисти главу», «прибери ШІ з тексту» |
| Перевірити текст, власний чи згенерований | «Чи звучить це як ШІ?», «перевір мій текст», «перевір згенерований текст» |
| Знайти кальки | «Діагностика кальок у главі» |
| Перевірити лише один рівень | «Перевір будову глави», «перевір тільки діалоги» |
| Прочитати главу очима читача | «Тест читача», «прожени главу очима читача» |

Аудит повертає таблицю знахідок, а не переписаний текст: що правити, вирішує
автор.

## Як це виглядає

> **До:** Варто зазначити, що резервне копіювання відіграє ключову роль
> у забезпеченні надійності інфраструктури. Здійснення резервного копіювання
> відбувається щоночі за допомогою скрипта `backup.ps1`, що дозволяє мінімізувати
> ризики втрати даних. Таким чином, наше рішення є надійним, масштабованим
> і гнучким.
>
> **Після:** Резервну копію щоночі знімає скрипт `backup.ps1`.
>
> **Питання до автора:** скільки даних можна втратити за такої схеми (RPO)
> і скільки триває відновлення? Речення про надійність прибрано, бо в ньому
> не було факту.

Кожна знахідка має номер пункту правил: `1.1 · S1` — підводка, `1.2 · S2` —
віддієслівний іменник, `1.9 · S2` — примусова трійка. Повний розбір цього
абзацу й аудит художнього уривка — у [docs/examples.md](docs/examples.md).

## Чим відрізняється

- **Питає, а не вигадує.** Чого бракує в тексті (числа, назви, деталі сцени),
  те стає питанням до автора, а не правдоподібною вставкою.
- **Зміст важливіший за стиль.** Після чистки скіл звіряє результат з
  оригіналом: чи не зникли факт, умова, обмеження, маркер невизначеності.
- **Вага ознак.** Не кожна ознака — дефект: одні правляться з першої появи,
  інші лише тоді, коли скупчилися. Так скіл не вичищає живий авторський текст.
- **Кальки — окремим проходом.** Таблиця підозр із нормою та впевненістю,
  вердикт за автором. Спірні пари звірено зі словниками.
- **Крок не губиться.** Кожен скіл закінчує роботу рядком стадій — переліком
  файлів, які справді прочитано. Пропущена стадія видна в рядку. Хук плагіна
  не дає закінчити хід, у якому зібрано .docx, .xlsx чи .pdf без мовного
  проходу по остаточному тексту.
- **Два жанри — два плагіни.** Технічний текст і художня проза мають різні
  правила: розмовна репліка героя чи свідомий повтор у прозі — прийом, а не вада.

## Як перевіряється

Набори тестів лежать у [tests/](tests/). Для технічного скіла — 24 синтетичні
випадки: мовна правка й аудит, джерела й фактчекінг, жанри й вивантаження,
а також тексти, які правити не треба. Для художнього — 6 людських уривків,
які скіл не має «виправляти». Критерії записано до першого прогону,
виконавець їх не бачить.

Скіл позначив те, що вадою не є? Відкрийте issue за шаблоном «Хибне
спрацювання»: підтверджений випадок стає контрприкладом у самому правилі.

## Встановлення

### Claude Code

```
/plugin marketplace add alexgorby/claude-skills
/plugin install ukrainian-tech-docs@alexgorby-skills
/plugin install ukrainian-fiction@alexgorby-skills
```

Скіл вмикається сам, коли ви просите написати, перевірити чи почистити
український текст відповідного жанру.

### Claude Desktop і claude.ai

Відкрийте чат (не вкладку Code), далі налаштування → Плагіни → «Додати» →
додати маркетплейс, у поле URL — `alexgorby/claude-skills` або
`https://github.com/alexgorby/claude-skills`. Після цього обидва плагіни
з'являться на вкладці «Огляд», кнопка «Додати» ставить потрібний.

Важливо, звідки додавати. Маркетплейс, доданий із чату, зберігається в обліковому
записі claude.ai, і плагін видно в чаті, Cowork і Claude Code. Доданий, коли
активна вкладка Code, ляже лише на цей комп'ютер і в чаті його не буде.

Плагін оновлюють вручну через меню: Плагіни → «⋮» біля плагіна → перевірити оновлення → «Оновити».

Під час додавання чи оновлення технічного плагіна Claude Desktop попереджає,
що плагін «містить компоненти, які виконують код». Йдеться про хук
`hooks/check_language_pass.py`. Наприкінці кожного ходу Claude в сесіях на
вашому комп'ютері він читає журнал поточної сесії. Якщо в ході зібрано
`.docx`, `.xlsx` чи `.pdf`, а після останньої зміни тексту мовного проходу не
було, хук повертає Claude вимогу пройти мову. Інакше він нічого не робить.
Файлів хук не змінює, до мережі не звертається. Запускається він командою
`python`, тож Python має бути в `PATH`.

Агенти рецензії і хук мовного проходу працюють і в Claude Code, і в чаті
Claude Desktop: так показала перевірка 02.11.2026, хоча таблиця сумісності в
документації Anthropic для чату пише «ігнорується». Чат claude.ai у браузері
окремо не перевіряли.

Інший шлях — завантажити скіли архівами: налаштування → Skills → додати власний
скіл. Архіви збирає `pwsh ./build.ps1` у теку `dist/`: для технічного пакета —
сім архівів, по одному на скіл, кожен зі своєю копією спільних правил. Архіви не
містять агентів і хука: рецензія йде без субагентів, а про мовний прохід перед
вивантаженням нагадує лише рядок стадій. Завантаження архівів не перевіряли:
стаття підтримки claude.ai називає межу опису скіла в 200 знаків, а описи скілів
пакета довші. Не тримайте одночасно плагін й архівну копію того самого скіла:
Claude бачитиме два однакові скіли.

### Codex

Codex читає той самий маркетплейс, окремої редакції для нього немає:

```
codex plugin marketplace add alexgorby/claude-skills
codex plugin add ukrainian-tech-docs@alexgorby-skills
codex plugin add ukrainian-fiction@alexgorby-skills
```

Знімок маркетплейсу оновлює `codex plugin marketplace upgrade`.

Перевірено 27.10.2026, Codex 0.164, на попередній будові з одним скілом:
скіл вмикається і читає правила, але звіт дотримується їх не повністю. Будову
із шести скілів у Codex як плагін ще не перевіряли; агенти й хук там,
імовірно, не працюють.

### Інші агенти

Скіл — звичайна тека з `SKILL.md`. Скіли технічного пакета читають спільну
теку `shared/` плагіна, тож окремо від плагіна беріть теку з архіву, який
збирає `build.ps1`: там `shared/` уже всередині.

## Джерела

Правила написано наново українською. Ідеї частково взято з досліджень і чужих
скілів; англомовні правила перенесено лише там, де вони працюють для української.
Повний перелік із посиланнями — у `SOURCES.md` технічного плагіна (для рецензії —
ще розділ «Джерела» в `skills/review/SKILL.md`) і в розділі «Джерела пакета»
у `SKILL.md` художнього скіла.
